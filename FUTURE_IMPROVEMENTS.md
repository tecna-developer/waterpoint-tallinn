# WaterPoint Tallinn — список улучшений на будущее

Актуально на 16.08.2026. Документ описывает технический и продуктовый долг
демонстрационного прототипа. Задачи расположены в рекомендуемом порядке.

## Уже решено

- [x] Неподтверждённые точки больше не помечаются как доступные.
- [x] Время синхронизации подписано как «Данные обновлены», а не «Проверено».
- [x] Форма проблемы работает в честном демо-режиме и ничего не отправляет.
- [x] Контактные данные и согласие на несуществующую модерацию удалены из формы.
- [x] Локальные демонстрационные отметки можно удалить в настройках.
- [x] Пустой фильтр «Доступно сейчас» скрыт до появления подтверждённых статусов.
- [x] Маркеры на карте, легенда и бейджи приведены в соответствие со статусом
  `unknown` по умолчанию: цвет маркера снова показывает категорию (вода/туалет),
  а не гаснет в серый у всех 174 точек; легенда не описывает статус `available`,
  которого структурно не бывает без бэкенда; бейдж «не подтверждено» убран из
  карточек списка (был шумом на каждой строке) — сам факт остаётся у даты
  проверки в карточке точки.
- [x] Удалять экземпляр мини-карты Leaflet при закрытии или повторном рендере
  карточки — фиксировано счётчиком created/removed в консоли (6/6).
- [x] Сохранять позицию прокрутки после добавления точки в избранное — реализовано
  универсально в `render()` для любого ререндера той же вью, не только избранного.
- [x] Шторки (фильтры, форма жалобы) больше не исчезают, если фоновое событие
  (online/offline, завершившийся `sync()`) вызовет `render()` поверх открытой формы —
  `render()` теперь перезаписывает только `#view-root`, шторки — соседний узел.
- [x] Системная и in-app кнопка «Назад» больше не закрывают приложение из карточки
  точки — `history.pushState`/`popstate`, единая точка выхода из detail-вью.
- [x] Сортировка «Недавно добавленные» удалена: `source_object_id` — внутренний id
  ArcGIS, а не дата; после слияния слоёв она просто группировала точки по категории.
- [x] `fmtDist()` показывал «м»/«км» захардкоженно по-русски на каждой карточке с
  расстоянием, независимо от языка интерфейса — на EN/ET экранах выглядело забытой
  отладочной строкой. Единицы и десятичный разделитель теперь идут через
  `t()`/новый общий `localeTag()` в i18n.js (там же убрал дублирующий приватный
  `locale()` в main.js — использовал ту же функцию для дат).

## P1 — исправить до публичной демонстрации

### Точка отсчёта и поиск

- [ ] Заменить конкурирующие `userPos` и `searchPos` на единый `activeOrigin` с типом
  `gps`, `search` или `manual` (пока чинил только приоритет и обратный переход между
  ними точечно — см. «Уже решено»; полноценного единого поля со `state.originKind`
  всё ещё нет, читать его в других местах кода по-прежнему приходится через `if`).
- [x] При выборе адреса или района пересчитывать расстояния от результата поиска,
  даже если ранее была разрешена геолокация — `origin()` в data.js теперь предпочитает
  `searchPos`; было наоборот: разрешённый GPS немо перебивал любой выбор в поиске,
  расстояния и «ближайшие» карточки молча продолжали считаться от GPS.
- [x] Кнопкой «Моё местоположение» явно возвращать GPS как активную точку отсчёта —
  `requestGeo(interactive=true)` очищает `searchPos`.
- [x] Не показывать сортировку «Ближайшие» как активную, если точка отсчёта
  отсутствует — сам переключатель сортировки убран (см. выше, фиктивная
  «Недавно добавленные» вместе с «Ближайшие» заменены единственным сортом по
  расстоянию, который и так уже был поведением по умолчанию).

Готово, когда карта, расстояния и сортировка всегда используют одну и ту же явно
показанную пользователю точку отсчёта.

### Надёжный офлайн-режим PWA

- [ ] Подключить Workbox или `vite-plugin-pwa` для генерации precache-манифеста.
- [ ] Кешировать HTML, JS, CSS, иконки и встроенные JSON-снапшоты.
- [ ] Использовать navigation fallback только для HTML-навигации; не возвращать
  `index.html` вместо отсутствующих JS/CSS-файлов.
- [ ] Использовать `NetworkFirst` для GIS-запросов и `CacheFirst` для оболочки.
- [ ] Добавить уведомление о доступной новой версии приложения.
- [ ] Проверить первый офлайн-запуск сразу после установки PWA.

Готово, когда установленное приложение открывает карту, список и карточки без сети,
даже если после установки его ещё ни разу не перезагружали онлайн.

### Доступность

- [ ] Сделать единый менеджер bottom sheet/dialog: `aria-modal`, перенос фокуса,
  focus trap, Escape, возврат фокуса и блокировка прокрутки фона.
- [ ] Разделить карточку точки и кнопку избранного: не вкладывать интерактивный
  элемент в другой `<button>`.
- [ ] Добавить заметные стили `:focus-visible` для кнопок, чипов, ссылок и полей.
- [ ] Добавить `aria-pressed` выбранным чипам и кнопкам избранного.
- [ ] Реализовать клавиатурное управление табами категорий либо заменить `role="tab"`
  на обычную группу кнопок.
- [ ] Поднять контраст основного синего, warning-текста, WC-бейджей и вторичного
  текста до WCAG AA.
- [ ] Проверить интерфейс screen reader и автоматическим accessibility-аудитом.

Готово, когда весь основной сценарий выполняется только клавиатурой, фокус всегда
видим, а текст нормального размера имеет контраст не ниже 4.5:1.

### Карта

- [ ] Добавить кластеризацию маркеров на общегородском масштабе.
- [ ] Раскрывать отдельные точки при приближении или выборе кластера.
- [ ] Сохранять читаемость выбранного маркера поверх соседних маркеров.
- [ ] Проверить производительность карты на 300–500 точках.

Готово, когда центр Таллина не перекрыт маркерами и нужную точку можно выбрать без
нескольких случайных нажатий.

## P2 — стабилизация проекта

### Рендеринг и состояние интерфейса

- [ ] Перестать заменять весь `#view-root.innerHTML` при каждом изменении состояния
  (частично смягчено: шторки и главная карта уже не пересоздаются, см. «Уже решено»).
- [ ] Обновлять только изменившуюся карточку, счётчик, список или слой маркеров.
- [ ] Использовать делегирование событий вместо повторного навешивания обработчиков.
- [ ] Отменять устаревшие запросы поисковых подсказок через `AbortController`.
- [ ] Пушить историю и для смены нижних вкладок (map/list/saved/settings), не только
  для карточки точки — сейчас «назад» с любой вкладки, кроме detail, закрывает
  приложение; для detail это уже исправлено.

### Архитектура

- [ ] Разделить `main.js` на состояние, карту, поиск, список/карточки, настройки,
  локальные отметки и общие UI-компоненты.
- [ ] Отделить доменную модель точки от формата ответа Tallinn GIS.
- [ ] Добавить единый слой хранения с безопасной обработкой ошибок `localStorage`.
- [ ] Задокументировать допустимые значения статусов и источник каждого статуса.
- [ ] Рассматривать переход на React/Vue только при заметном росте продукта; сначала
  устранить связанность текущего кода.

### Качество данных

- [ ] Определить границу продукта: только Tallinn или также Maardu и Saue.
- [ ] Проверять и агрегировать совпадающие координаты, например несколько туалетов
  в одной точке пляжа.
- [ ] Различать несколько объектов в одном месте количеством или дополнительной
  подписью, а не дублировать одинаковые карточки.
- [ ] Валидировать живой ответ GIS перед перезаписью последнего хорошего кеша.
- [ ] Хранить отдельно время загрузки данных и дату физической проверки объекта.
- [ ] Подтвердить условия повторного использования обоих GIS-слоёв.

### Сортировки и фильтры

- [ ] Показывать активные фильтры одним понятным набором и сбрасывать несовместимые
  фильтры при смене категории.
- [ ] Объяснять, почему недоступны фильтры, для которых источник не даёт данных.
- [ ] Синхронизировать важные фильтры с URL (карточка точки — уже `?p=<id>`).

### Автоматические проверки

- [ ] Добавить Vitest для сезонности, статусов, расстояний, сортировок, фильтров,
  нормализации GIS и частичного сбоя синхронизации.
- [ ] Добавить Playwright для onboarding, поиска после GPS, избранного, диалогов,
  deep link и офлайн-запуска.
- [ ] Добавить ESLint, форматирование и проверку переводов.
- [ ] Запускать сборку, тесты и accessibility-проверку в CI перед деплоем.

## P3 — продуктовый и визуальный polish

- [ ] Принять окончательное название продукта: WaterPoint Tallinn или VeeLähedal.
- [ ] Обновить title, manifest, Open Graph, иконки и описание: продукт уже показывает
  не только воду, но и туалеты.
- [ ] Уменьшить декоративный hero карточки, пока у точек нет настоящих фотографий.
- [ ] Поднять источник, дату обновления и дисклеймер статуса ближе к основным данным.
- [ ] Добавить планшетную/десктопную компоновку либо явно зафиксировать mobile-only.
- [ ] Оптимизировать длинный список через `content-visibility` или виртуализацию.
- [ ] Добавить `prefers-reduced-motion` для skeleton и анимации bottom sheet.
- [ ] Добавить корректный `color-scheme` и отдельные `theme-color` для светлой и
  тёмной темы PWA.
- [ ] Проверить RU/ET/EN на переполнение, грамматику и единообразие терминов.

## Если прототип станет реальным сервисом

- [ ] Добавить backend для жалоб и очередь модерации.
- [ ] Хранить `operational_status`, `status_source`, `data_updated_at` и
  `physically_verified_at` раздельно.
- [ ] Показывать `available` только при подтверждении официальным источником или
  модератором.
- [ ] Добавить политику хранения и удаления пользовательских данных.
- [ ] Защитить публичную форму серверным rate limit и антиспамом.
- [ ] Добавить мониторинг синхронизации GIS и ошибок клиентского приложения.

До появления backend форма должна оставаться явно обозначенной как локальная
демонстрация и не должна собирать контактные данные.
