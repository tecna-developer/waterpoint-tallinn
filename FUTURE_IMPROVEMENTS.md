# WaterPoint Tallinn — список улучшений на будущее

Актуально на 18.08.2026. Документ описывает технический и продуктовый долг
демонстрационного прототипа. Задачи расположены в рекомендуемом порядке.

Отмеченное `[x]` — сделано и проверено; в таких пунктах намеренно записано, **что
именно** было не так, потому что почти всё здесь выглядело исправным до проверки.

## Уже решено

- [x] Неподтверждённые точки больше не помечаются как доступные.
- [x] Время синхронизации подписано как «Данные обновлены», а не «Проверено».
- [x] Форма проблемы работает в честном демо-режиме и ничего не отправляет.
- [x] Контактные данные и согласие на несуществующую модерацию удалены из формы.
- [x] Локальные демонстрационные отметки можно удалить в настройках.
- [x] Пустой фильтр «Доступно сейчас» скрыт до появления подтверждённых статусов.
- [x] Маркеры на карте, легенда и бейджи приведены в соответствие со статусом
  `unknown` по умолчанию: цвет маркера снова показывает категорию (вода/туалет),
  а не гаснет в серый у всех 174 точек; легенда не описывает статус `available`,
  которого структурно не бывает без бэкенда; бейдж «не подтверждено» убран из
  карточек списка (был шумом на каждой строке) — сам факт остаётся у даты
  проверки в карточке точки.
- [x] Удалять экземпляр мини-карты Leaflet при закрытии или повторном рендере
  карточки — фиксировано счётчиком created/removed в консоли (6/6).
- [x] Сохранять позицию прокрутки после добавления точки в избранное — реализовано
  универсально в `render()` для любого ререндера той же вью, не только избранного.
- [x] Шторки (фильтры, форма жалобы) больше не исчезают, если фоновое событие
  (online/offline, завершившийся `sync()`) вызовет `render()` поверх открытой формы —
  `render()` теперь перезаписывает только `#view-root`, шторки — соседний узел.
- [x] Системная и in-app кнопка «Назад» больше не закрывают приложение из карточки
  точки — `history.pushState`/`popstate`, единая точка выхода из detail-вью.
- [x] Сортировка «Недавно добавленные» удалена: `source_object_id` — внутренний id
  ArcGIS, а не дата; после слияния слоёв она просто группировала точки по категории.
- [x] `fmtDist()` показывал «м»/«км» захардкоженно по-русски на каждой карточке с
  расстоянием, независимо от языка интерфейса — на EN/ET экранах выглядело забытой
  отладочной строкой. Единицы и десятичный разделитель теперь идут через
  `t()`/новый общий `localeTag()` в i18n.js (там же убрал дублирующий приватный
  `locale()` в main.js — использовал ту же функцию для дат).
- [x] Текст о приватности в настройках безусловно утверждал «ничего не отправляем
  на сервер». Неточно: поиск адреса, не найденного среди точек/районов приложения,
  безусловно шлёт введённый пользователем текст на `nominatim.openstreetmap.org`
  (`buildSuggestions` в main.js) — сторонний домен, не упомянутый нигде в тексте о
  приватности. GPS-координаты туда действительно не попадают (это утверждение было
  верным), но сам факт стороннего запроса должен быть виден пользователю, а не
  только в комментарии к коду. Добавил уточнение в `settings_privacy_text` на всех
  трёх языках.

## P1 — исправить до публичной демонстрации

### Точка отсчёта и поиск

- [x] Заменить конкурирующие `userPos` и `searchPos` на единый `activeOrigin` с типом
  `gps`, `search` или `manual` — `origin()` в data.js теперь просто возвращает
  `state.activeOrigin`, вся логика приоритета (явный выбор в поиске/на карте сильнее
  фонового GPS, «Моё местоположение» явно возвращает GPS) переехала в момент записи,
  а не чтения. Отдельно оставлен `state.gpsPos` — это не альтернативный источник для
  расстояний, а физическая позиция устройства для точки на карте; она обновляется даже
  когда активна точка отсчёта из поиска, и `activeOrigin` через него не подмешивается.
- [x] При выборе адреса или района пересчитывать расстояния от результата поиска,
  даже если ранее была разрешена геолокация — `origin()` в data.js теперь предпочитает
  `searchPos`; было наоборот: разрешённый GPS немо перебивал любой выбор в поиске,
  расстояния и «ближайшие» карточки молча продолжали считаться от GPS.
- [x] Кнопкой «Моё местоположение» явно возвращать GPS как активную точку отсчёта —
  `requestGeo(interactive=true)` очищает `searchPos`.
- [x] Не показывать сортировку «Ближайшие» как активную, если точка отсчёта
  отсутствует — сам переключатель сортировки убран (см. выше, фиктивная
  «Недавно добавленные» вместе с «Ближайшие» заменены единственным сортом по
  расстоянию, который и так уже был поведением по умолчанию).

Готово, когда карта, расстояния и сортировка всегда используют одну и ту же явно
показанную пользователю точку отсчёта.

### Надёжный офлайн-режим PWA

- [x] Navigation fallback только для HTML-навигации — главный баг воркера: `catch`
  отдавал `./index.html` в ответ на ЛЮБОЙ упавший запрос, включая JS и CSS. Браузер
  получал HTML вместо модуля и падал с SyntaxError — вместо честной ошибки сети
  пользователь видел белый экран. Теперь фолбэк только при `request.mode === 'navigate'`.
- [x] `CacheFirst` для оболочки — точнее, для файлов сборки с хешем содержимого в имени
  (`assets/index-<hash>.js`): по такому URL всегда лежит одно и то же. Было
  network-first на всё, то есть запуск установленного PWA на плохой связи ждал сеть
  даже при полностью закешированной оболочке.
- [x] Не кешировать ответы с ошибкой — раньше 404/5xx оседал в кеше до смены версии.
- [x] Кешировать файлы сборки на этапе `install` — раньше в precache были только `./`
  и `./index.html`, то есть оболочка была неполной. Это и дало белый экран на телефоне:
  PWA стартует, получает свежий `index.html` со ссылкой на новый бандл, а бандл ещё не
  разошёлся по CDN — скрипт не грузится, в кеше его нет, экран пустой. Хеши заранее
  неизвестны, поэтому воркер вычитывает их из самого `index.html`; каждый файл
  кешируется отдельно, чтобы один недоступный не отменил остальные (`cache.addAll`
  отменяет всё). Кеш поднят до `wpt-shell-v4`.
- [x] Выход из белого экрана — в `index.html` добавлен аварийный блок **вне бандла**
  (он обязан работать именно тогда, когда бандла нет): через 8 с пустого экрана
  показывает сообщение на трёх языках и кнопку, которая чистит кеши, снимает воркер и
  перезагружает. Обычная перезагрузка тут не помогает: оболочка собрана из
  несовместимых версий файлов.
- [x] Подключить `vite-plugin-pwa` для генерации precache-манифеста — режим
  `injectManifest`: список файлов подставляется на сборке, а воркер остаётся своим
  (`src/sw.js`, переехал из `public/`), со всеми его решениями. Разбор `index.html`
  регуляркой убран целиком; он требовал сети прямо во время `install` и молча давал
  неполную оболочку, если запрос срывался. Цена — 322 пакета в devDependencies и
  ~2.3 КБ gzip в бандле (`workbox-window`, за ним стоит определение новой версии);
  модули кеширования Workbox в браузер не уезжают.
- [x] Кешировать иконки PWA на этапе `install` — закрылось тем же манифестом
  (`globPatterns` включает png/svg/webmanifest). Проверено в браузере, а не только на
  моках: после установки в `wpt-shell-v5` лежат все файлы оболочки, включая четыре
  иконки и `manifest.webmanifest`.
- [x] Исключить `og.png` из precache (`globIgnores`) — под шаблон `png` он попадал, а
  в оболочке ему делать нечего: баннер Open Graph читают краулеры соцсетей по прямой
  ссылке, само приложение не запрашивает его никогда. При этом он весил больше всех
  остальных файлов оболочки вместе взятых: 459.8 → 363.8 КБ, то есть офлайн-установка
  на пятую часть состояла из картинки, которую пользователь никогда не увидит.
  Проверено на чистой установке (со снятым воркером и удалёнными кешами — старые кеши
  от прошлых прогонов иначе показывают ложную картину): в `wpt-shell-v5` 11 файлов
  вместо 12, `og.png` среди них нет, но по прямой ссылке он по-прежнему отдаётся 200.
- [x] Добавить уведомление о доступной новой версии приложения. Заодно убран
  безусловный `skipWaiting()` в `install`: он подменял воркер под уже запущенной
  страницей, которая успела загрузить чанки прошлой сборки — ровно тот случай
  «оболочка из несовместимых версий», ради которого в `index.html` живёт аварийный
  блок. Теперь новый воркер ждёт, страница показывает баннер, и `SKIP_WAITING`
  уходит только по нажатию. Проверен весь цикл в браузере: новая сборка → воркер в
  состоянии `waiting` → баннер → нажатие → активация, удаление старого кеша,
  перезагрузка.
- [ ] Проверить первый офлайн-запуск сразу после установки PWA на реальном устройстве —
  логика воркера покрыта `npm run test:sw`, но это мок-окружение, не настоящий Safari/Chrome.
- [x] Нормализовать ключ кеша для навигаций с query — `cacheKey()` в `src/sw.js`.
  `putIfOk` клал ответ по полному URL, поэтому каждая расшаренная ссылка вида
  `?p=<id>` (FR-13) оседала в кеше **отдельной копией** `index.html`; замечено на живом
  демо, куда попал даже разовый диагностический запрос `index.html?_=1787327419245`.
  При 174 точках кеш в пределе распухал до 174 одинаковых оболочек. Query отбрасывается
  только у навигаций — у обычных запросов он может быть значимым, и на это есть
  отдельный тест. Побочная выгода: нормализованный ключ совпадает с `'./'` из precache,
  поэтому офлайновый deep link находит оболочку сразу, не доходя до SPA-фолбэка.
  Кеш поднят до `wpt-shell-v6`, чтобы прежние записи с query вычистились в `activate`.
  Проверено в браузере: три настоящие навигации по разным `?p=` не добавили в кеш ни
  одной записи (11 до, 11 после, записей с query нет), а сама ссылка по-прежнему
  открывает нужную карточку.

Готово, когда установленное приложение открывает карту, список и карточки без сети,
даже если после установки его ещё ни разу не перезагружали онлайн.

### Доступность

- [x] `aria-modal`, перенос фокуса, Escape, возврат фокуса — у фильтров (`openFilterSheet`)
  и формы жалобы (`openReportSheet`) теперь одинаково. У фильтров был баг серьёзнее,
  чем просто «нет Escape»: `draw()` полностью пересоздаёт `innerHTML` шторки на каждый
  клик по чипу, и без явного восстановления фокус проваливался на `<body>` после
  **первого же** клика внутри — не только при открытии/закрытии, а на каждом
  взаимодействии; чинить пришлось по атрибуту-идентификатору кликнутого чипа.
  (Дублирование кода и блокировка прокрутки, остававшиеся здесь как TODO, закрыты
  следующими двумя пунктами.)
- [x] Вынести общий код шторок в одну функцию — `openSheet()`; `openFilterSheet` и
  `openReportSheet` больше не повторяют паттерн независимо. Заодно выяснилось, что
  выносить было почти нечего: `aria-modal="true"` обе шторки объявляли, а выполнить
  не могли ничем. Замер при открытой шторке: **55 фокусируемых элементов на фоне**
  (карта, её маркеры, нижняя навигация, поиск), Tab спокойно уходил туда — то есть
  модальность была только на словах, как когда-то у `role="tab"`. Закрыто через
  `inert` на `#view-root`: он убирает фон и из tab-порядка, и из дерева доступности
  разом, так что скринридеру не приходится верить `aria-modal` на слово.
- [x] Блокировка прокрутки фона под шторкой — нужна была: `.view` прокручивался
  под открытой шторкой (замер `scrollTop` 0 → 600). Привычное `body { overflow: hidden }`
  здесь ничего не держит: `body` и `#app` уже `overflow:hidden` с `height:100dvh`,
  прокручивается только `.view`. Класс висит на `#app`, а не на самом `.view`:
  `.view` пересоздаётся каждым `render()`, и фоновое событие (завершившийся `sync`,
  online/offline) сняло бы блокировку прямо под открытой шторкой.
- [x] Возврат фокуса при закрытии шторки — здесь нашлась настоящая дыра, которой не
  было в этом списке. Самые обычные способы закрыть шторку («Показать N», «Закрыть»
  после отправки отчёта) вызывают `render()` сразу за `close()`, а `render()`
  перезаписывает `#view-root` целиком и уничтожает ту самую кнопку, на которую фокус
  только что вернули. Оба пути оставляли фокус на `<body>` — то есть клавиатурный
  пользователь терял место в интерфейсе именно в самом частом сценарии, а не в
  краевом. `close()` теперь принимает ререндер колбэком и выполняет его до возврата
  фокуса, а если узел всё же исчез — ищет триггер заново по `id`. Отдельно: экран
  «отчёт отправлен» заменял `innerHTML` шторки, никуда не перенося фокус, а его
  кнопка «Закрыть» звала `overlay.remove()` напрямую и оставляла фон инертным.
- [x] Разделить карточку точки и кнопку избранного: не вкладывать интерактивный
  элемент в другой `<button>` — было `<span role="button">` без `tabindex` внутри
  настоящей `<button>` (карта, список, избранное); с клавиатуры избранное было
  недостижимо вообще, добавить точку в избранное можно было только открыв её
  карточку. `.card`/`.map-card` теперь неинтерактивный контейнер с двумя
  кнопками-соседями (`.card-open`/`.map-card-open` и `.heart`/`.go`).
- [x] Заметные стили `:focus-visible` — общий ринг с токеном `--focus-ring` (тёмный
  на светлой теме, светлый на тёмной). Формулировка «нативный контур ничем не подавлен»
  оказалась неверной: `.search-bar input` гасил `outline` **безусловно и без замены**,
  так что у поля поиска не было индикатора фокуса вообще (проверил настоящей клавишей
  Tab: элемент в `:focus-visible`, а `outline-style: none`). Кольцо для поля рисуем на
  всей строке поиска — у самого `input` нет ни рамки, ни фона. У `.field` полей смена
  цвета рамки осталась как акцент, но она больше не единственный признак фокуса.
  Кольцу нужно 5px наружу, а строка чипов на карте — горизонтальный скроллер с нулевым
  вертикальным отступом (`overflow-x:auto` включает и `overflow-y:auto`), поэтому там
  кольцо срезалось; добавил padding под него, компенсированный отрицательным margin,
  чтобы вёрстка не сдвинулась.
- [x] Добавить `aria-pressed` кнопкам избранного и всем чипам-переключателям:
  категории, «доступно сейчас», избранное, радиус, тип — и на экранах, и в шторке
  фильтров. Раньше включённость передавалась только цветом (`.on`), то есть для
  скринридера все чипы звучали одинаково и выбранный фильтр не озвучивался никак.
- [x] Заменил `role="tab"`/`role="tablist"` у переключателя категорий на обычную
  группу кнопок (второй вариант из этого пункта). Проверил, что это был именно
  невыполненный контракт, а не придирка: стрелки не работали (ArrowRight не двигал
  фокус), `role="tabpanel"` и `aria-controls` отсутствовали вовсе, а все три кнопки
  сидели в tab-порядке вместо roving tabindex. По сути это и не вкладки — контрол
  фильтрует ту же карту и список на месте, панелей для переключения нет.
- [x] Контраст до WCAG AA — 0 провалов в обеих темах, проверено скриптом
  `scripts/contrast-audit.js` (обходит реально отрисованный DOM, а не список догадок).
  Фирменный синий затемнён с `#2d9cdb` до `#1a76a8`: белый текст на прежнем давал 3.05
  при норме 4.5, то есть **все** залитые кнопки и активные чипы формально были
  нечитаемы. В тёмной теме заливка осталась светлой, а текст на ней стал тёмным
  (`--on-primary`) — там белый давал 2.68. Отдельно: `--text-muted`, `--primary-strong`
  на soft-фоне, зелёный туалетов, выбранный язык в настройках, атрибуция Leaflet
  (её читаемость — требование лицензии OSM/CARTO, а не декор). Цвет синхронизирован
  с маркерами карты, `theme-color` и manifest.
- [x] Заново отрисовать `public/og.png` — баннер был последним местом, где уцелел
  прежний `#2d9cdb`: растр за токенами не следует. Перерисован не только в цвете.
  Подпись гласила «Общественные питьевые краны Таллина», хотя 96 из 174 точек —
  туалеты: та же «только про краны», которую уже правили в meta description и
  `settings_about_text`. И одна капля больше не описывает продукт из двух категорий,
  поэтому знак теперь — два маркера карты, каждый своей формы и цвета из `icons.js`,
  а не смешанный символ (§7.2 запрещает смешивать типы точек визуально). Галочка
  внутри капли осталась: в `icons.js` это опознавательный глиф категории «вода»
  (парный к «WC» у туалетов), а не утверждение о статусе — проверил, прежде чем убирать.
  Исходник разметки положен в `scripts/og-source.html`, чтобы следующая смена цвета
  пересобирала баннер, а не перерисовывала его на глаз.

- [x] Проверить интерфейс скринридера — по дереву доступности, а не на слух: живой
  VoiceOver/TalkBack отсюда не запустить, поэтому смотрел то же, что читает скринридер.
  Нашлось то, чего axe не видит в принципе: **кластеры на карте озвучивались голым
  числом** — «2», «27», и таких кнопок на общем виде 26 подряд, без единого намёка, что

  кружки со счётчиками. Автонаведение отменяется, как только пользователь сам задал вид.
  Отдельно пришлось учесть, что выбор в поиске и «показать на карте» — тоже осознанное

- [x] Слой поверх карты сведён в один поток (`.map-overlay-top`). Были два блока с

  поиска не выше 50px. При крупном системном шрифте она выше, и блоки наезжали друг на
  друга (замер: при высоте строки 94px наложение 42px).
- [ ] Оформление кластеров сделано своё (плагинную тему не подключали): плагин не знает
  ни про тёмную тему, ни про контраст, ни про различение категорий. Если появятся новые
  состояния кластеров — стили держать в `styles.css` рядом с `.wp-cluster`.
- [ ] **Кластеры отстают от зума — снято на реальном устройстве.** На скриншоте с телефона
  кластер «56» поверх карты уровня улиц (видны отдельные дома, фильтр «Вода»).
  Это невозможно по данным: совпадающих координат у кранов нет вовсе, а в радиусе 1200 м
  от того места всего 10 кранов. Замеры по зумам для 78 кранов: z12 → максимум 13,
  z10 → 27, z8 → 53, z6 → 78 — то есть 56 соответствует зуму 7–8, виду на весь регион.
  Значит кластеры построены для далёкого зума и не перестроились, а тайлы обновились:
  рассогласование примерно в семь уровней.
  Локально **не воспроизводится**: при обычном зумировании перестроение корректно
  (z12 → 13, z14 → 2, z16 → 2, z18 → 0). Подозрение на прерванный кадровый цикл —
  `markercluster` анимирует перестроение через `requestAnimationFrame`, а тот
  останавливается у свёрнутого PWA и при энергосбережении (на скриншоте батарея 19%).
  Это уже третий случай того же класса в проекте: так же вели себя тайлы карты
  (лечилось `fadeAnimation: false`) и анимация шторки.
  Варианты: (а) `animate: false` / `animateAddingMarkers: false` у `markerClusterGroup` —
  перестроение синхронное, но кластеры перестанут «разлетаться»; (б) вызывать
  `markerLayer.refreshClusters()` в `refreshMapAfterResume()`; (в) сверять зум, для
  которого построены кластеры, с текущим, и перестраивать при расхождении.

Готово: центр Таллина больше не залеплен маркерами, точка выбирается с первого нажатия.

### Пустая карта на телефоне

Симптом: карта не отображается, остальной интерфейс жив. Ловилось только на реальном
устройстве. Причину дали замеры с экрана (`window.wptMapDiagnostics()`): контейнер
схлопывался в нулевую высоту, а Leaflet держал размер 4121px.

- [x] Подпорка схлопнувшегося контейнера — `ensureMapSized()` сверяет размер Leaflet с
  фактическим и задаёт слоту явную высоту из доступного места. Подпорка снимается
  только после проверки, что высота держится без неё: первая версия правки снимала её
  сразу, высота падала обратно в 0, следующий вызов подставлял снова — колебание, и
  итог зависел от того, какой вызов был последним.
- [x] Перезапрос тайлов при возврате из фона (`refreshMapAfterResume()`). Проверка
  размеров этот случай закрыть не может по построению: она выходит, когда размеры
  совпадают, а при подъёме PWA из фона размер как раз верный — Android выбрасывает уже
  отрисованные тайлы, DOM-узлы остаются, и Leaflet ничего не перезапрашивает.
- [x] `fadeAnimation: false` — проявление тайлов идёт через `requestAnimationFrame`, а
  у свёрнутого PWA кадровый цикл останавливается: анимация могла остаться незавершённой,
  и тайлы висели с `opacity: 0` — загруженные, правильного размера и невидимые.
- [x] Баннер «фон карты не загрузился» — до этого пустое серое поле не объясняло
  ничего: обработчика `tileerror` не было вовсе.
- [ ] **Корневая причина схлопывания контейнера так и не найдена.** Всё перечисленное
  лечит симптом. Почему flex-цепочка `#app → #view-root → .map-view → слот` даёт ноль
  именно на этом устройстве — неизвестно; подозрение на `100dvh` при возврате из фона,
  но не проверено. Если сбой повторится, снимать `window.wptMapDiagnostics()` с экрана
  карты: ноль в `chain` укажет конкретное звено.
- [ ] Убрать `window.wptMapDiagnostics` из продакшена, когда корневая причина закрыта —
  сейчас это отладочный глобал, оставленный сознательно.
