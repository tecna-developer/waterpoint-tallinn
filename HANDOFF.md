# WaterPoint Tallinn — контекст проекта (handoff)

Саммери для продолжения работы в другой сессии.

## Что это
PWA-прототип для поиска общественных питьевых кранов **и общественных туалетов** в
Таллине. Сделан по макетам Stitch («WaterPoint Tallinn», светлая тема).

## Какому ТЗ соответствует
Актуальный документ — [`TZ_WaterPoint_Tallinn_with_public_toilets.md`](TZ_WaterPoint_Tallinn_with_public_toilets.md)
(«VeeLähedal», v0.1 от 05.07.2026, со слоем туалетов). **Важно:** более ранняя версия
ТЗ (v1.0 от 15.07.2026, `.docx`, в репозиторий не входит) использовала другую нумерацию
FR — там FR-11 была админ-панелью, а FR-12 аналитикой. Вся документация и комментарии в
коде приведены к нумерации актуального документа (FR-01…FR-17); при сверке со старыми
записями это первое место, где легко запутаться.

## Стек
Vite + ванильный JS (без фреймворка) + Leaflet (карта, тайлы CARTO/OSM) +
`leaflet.markercluster` (кластеризация маркеров, ~35 КБ gzip).
`vite-plugin-pwa` — только на сборке, в режиме `injectManifest`: подставляет
precache-манифест в собственный воркер `src/sw.js`. В браузер из него уезжает лишь
`workbox-window` (~2.3 КБ gzip) — определение новой версии для баннера обновления.
Деплой на GitHub Pages автоматически при пуше в `main` через `.github/workflows/deploy.yml`.

```bash
npm install
npm run dev       # http://localhost:5173 (порт бывает занят — Vite уйдёт на 5174)
npm run build     # сборка в dist/
npm run test:sw   # тесты service worker'а, без браузера
```

## Структура (`src/`)
- `main.js` — вся логика и рендер вью (онбординг, карта, список, карточка, избранное,
  настройки, фильтры, форма отчёта, легенда)
- `data.js` — конфиг слоёв, синхронизация с ArcGIS, кеш, localStorage, статусы, тема
- `data/waterpoints.json` — снапшот 78 кранов
- `data/toilets.json` — снапшот 96 туалетов
- `i18n.js` — строки ET/EN/RU, автовыбор языка, `localeTag()` для дат и чисел
- `icons.js` — SVG-иконки, `markerSvg(category, status, selected)`, `thumbSvg(category)`
- `styles.css` — стили, дизайн-токены, светлая/тёмная темы
- `sw.js` — service worker. Лежит в `src/`, а не в `public/`: сборка подставляет в него
  precache-манифест. В `dist/` попадает как `sw.js` рядом с `index.html`.

`scripts/`:
- `gen-toilets.mjs` — генерация снапшота туалетов из GIS (§6.4 ТЗ, ручное обновление)
- `test-sw.mjs` — тесты воркера на мок-окружении (`npm run test:sw`, 14 проверок).
  Исполняет исходник `src/sw.js` до подстановки манифеста — решения fetch-обработчика
  от содержимого манифеста не зависят.
- `contrast-audit.js` — аудит контраста по отрисованному DOM, запускается в консоли:
  `const a = await import('/scripts/contrast-audit.js'); await a.run();`
  Проверяет и редкие состояния, которых нет на экране (`auditHiddenStates()`).
- `a11y-audit.js` — аудит доступности (axe-core с CDN, только dev и только онлайн):
  `const a = await import('/scripts/a11y-audit.js'); await a.run();`
  Обходит все вью **и обе шторки** — половина находок первого прогона была в шторках,
  а на статичной странице их не видно. Сейчас 0 нарушений.

## Источники данных
Два независимых слоя Tallinn GIS ArcGIS REST в одной модели точки, различаются полем
`category` (§6.2 ТЗ):

| category | Слой | Точек |
|----------|------|-------|
| `water_tap` | `veebikaart/Veev6tukohad` | 78 |
| `public_toilet` | `veebikaart/avalikud_tualetid` (слой 0) | 96 |

Слой туалетов был открытым вопросом ТЗ (§13) — источник найден и проверён запросами.
Слой 0 является superset'ом: слой 1 («Statsionaarsed tualetid», 27 точек) целиком в него
входит по `objectid`, второй запрос не нужен. Из 106 записей 10 не имеют геометрии и
отбрасываются; остаются 69 временных и 27 стационарных.

Синхронизация слоёв независима (`Promise.allSettled`): сбой одного слоя не стирает
последнюю успешную копию другого. Районы вычислены point-in-polygon по `Linnaosad_asumid`.

**Чего в источниках нет:** часы работы, платность и доступность туалетов; миска для
собак и indoor/outdoor у кранов; фото. Всё это показывается как «нет данных» либо
скрывается (мёртвые фильтры), а не выдумывается — требование §6.3.

Временный туалет после даты демонтажа (`t2htaeg`) исчезает из выдачи — вести человека
к физически убранной точке хуже, чем не показать её.

**GIS не отдаёт CORS-заголовки для github.io**, поэтому на живом демо синхронизация
падает и работают встроенные снапшоты. В консоли это видно как ошибки CORS — они
обработаны, приложение показывает последнюю успешную копию.

## Карта: как устроена
- **Инстанс Leaflet переживает ререндеры.** `render()` перезаписывает только
  `#view-root`; контейнер карты (`mapEl`) хранится в переменной и переносится в новый
  слот, поэтому карта не пересоздаётся при каждом переключении фильтра.
- **Кластеризация** — радиус зависит от зума (`clusterRadius()`): 60px на общем виде,
  12px на z15 и ближе. Одним числом не обойтись: на общем виде центр превращается в
  кашу, а вблизи нужны сами точки. Совсем отключать вблизи нельзя — в данных две группы
  точно совпадающих координат (по три туалета на пляжах) и 13 пар ближе 15 м.
- **Цвет кластера называет состав:** однородный — цвет своей категории, смешанный —
  нейтральный (§7.2 запрещает смешивать типы точек визуально).
- **Выбранная точка не кластеризуется вовсе** — рисуется прямо на карте поверх
  остальных, иначе исчезала бы в кружке со счётчиком сразу после выбора.
- **Открывается на позиции пользователя** (`NEARBY_ZOOM = 15`), а не на общегородском
  виде. Автонаведение отменяется, как только пользователь сам задал вид — жестом,
  выбором в поиске или переходом «показать на карте» (`ui.mapMovedByUser`).
- **Слой поверх карты — один** (`.map-overlay-top`), внутри обычный поток. Раньше поиск
  и фильтры были двумя блоками с подобранными вручную `top`, и при крупном системном
  шрифте наезжали друг на друга.
- **Точка отсчёта одна — `state.activeOrigin`** (`{kind: 'gps'|'search'|'manual', lat,
  lng, label}`). `origin()` в data.js просто возвращает её; приоритет решается в момент
  записи, а не чтения: явный выбор в поиске или на карте сильнее фонового GPS, а
  «Моё местоположение» возвращает GPS явно. `state.gpsPos` — отдельное поле и НЕ запасной
  источник расстояний: это физическая позиция устройства для точки на карте, она
  обновляется даже когда активна точка отсчёта из поиска.

## Доступность и контраст
- Все интерактивные элементы проходят WCAG AA в обеих темах — проверяется
  `scripts/contrast-audit.js`, включая скрытые состояния (баннеры, статусные бейджи).
- **Фирменный синий затемнён** с `#2d9cdb` (макеты Stitch) до `#1a76a8`: белый текст на
  прежнем давал 3.05 при норме 4.5, то есть все залитые кнопки формально были нечитаемы.
  В тёмной теме заливка осталась светлой, а текст на ней стал тёмным (`--on-primary`).
- Цвет маркеров в `icons.js` держится в синхроне с токенами вручную — маркеры рисуются
  SVG-строкой, до CSS-переменных там не дотянуться.
- Кнопки-соседи вместо вложенных (`.card-open` + `.heart`), `aria-pressed` на
  переключателях, видимый `:focus-visible`.
- **axe-core: 0 нарушений** на всех вью и в обеих шторках (`scripts/a11y-audit.js`).
  Ориентиры (`<header><h1>`, `<main id="view-root">`) заданы статично в `index.html`,
  а не в `render()` — вью сменяются, и заголовок иначе пришлось бы дублировать.
- **Кластеры карты подписаны для скринридера** — «Точек воды: 2. Нажмите, чтобы
  приблизить» вместо голого «2» (на общем виде таких кнопок 26 подряд). Число скрыто
  `aria-hidden`, подпись лежит в `.sr-only` внутри иконки кластера. Формулировка
  «Точек: {n}» намеренно не требует склонения ни в одном из трёх языков.
- **Шторки — через общий `openSheet()`** (фильтры и форма жалобы). Он ставит `inert`
  на `#view-root`, чем и обеспечивает заявленный `aria-modal`: фон уходит и из
  tab-порядка, и из дерева доступности. Блокировка прокрутки — класс `sheet-open` на
  `#app`; вешать её на `.view` нельзя, тот пересоздаётся каждым `render()`.
  `close()` принимает ререндер колбэком и выполняет его **до** возврата фокуса —
  иначе `render()` уничтожает кнопку-триггер, на которую фокус только что вернули,
  и он падает на `<body>` (так было при «Показать N» и после отправки отчёта).
- `public/og.png` перерисован в новом синем. Растр за токенами не следует, поэтому
  исходник разметки лежит в `scripts/og-source.html` — при следующей смене цвета
  баннер пересобирается оттуда, а не перерисовывается на глаз.

## Замечания по окружению
- ОС Windows, оболочка PowerShell; git выдаёт предупреждения LF→CRLF (не критично).
  **Не использовать PowerShell для правки исходников** — `-replace` в этой сессии
  испортил кодировку кириллицы во всём `main.js`; правки делать редактором файлов.
- `gh` CLI **не авторизован** — операции через GitHub API недоступны, только git push/pull.
- Демо кешируется service worker'ом (`src/sw.js`). При релизе поднимать `CACHE`
  (сейчас `wpt-shell-v6`), иначе установленное PWA останется на старой оболочке.
  Список файлов оболочки воркер получает из precache-манифеста, собранного Vite —
  туда входят и бандл, и иконки PWA, и манифест. `og.png` намеренно исключён
  (`globIgnores` в vite.config.js): баннер читают краулеры соцсетей по прямой ссылке,
  приложению он не нужен, а весил он пятую часть оболочки.
- **Обновление больше не молчаливое.** Новый воркер намеренно не активируется сам
  (`skipWaiting()` из `install` убран): он ждёт, приложение показывает баннер
  «доступна новая версия», и только по нажатию уходит `SKIP_WAITING` с перезагрузкой.
  Поэтому сценарий «закрыть и открыть дважды» больше не нужен — но и молча на новую
  версию приложение само не перейдёт, пока пользователь не согласится.
  Баннер не показывается на экране онбординга: там пользователь ещё не начал работу.
- **Частые деплои подряд опасны для установленного PWA.** Каждая сборка меняет хеши
  файлов; если PWA стартует, когда свежий `index.html` уже отдаётся, а бандл ещё не
  разошёлся по CDN, скрипт не загружается. На этот случай в `index.html` есть аварийный
  блок (вне бандла): через 8 с пустого экрана показывает сообщение и кнопку, которая
  чистит кеши, снимает воркер и перезагружает.

## Отладка «карта не отображается»
Сбой воспроизводится только на реальном телефоне: в headless-окружении страница всегда
`document.hidden === true`, ветка «возврат PWA из фона» недостижима, а `requestAnimationFrame`
и `ResizeObserver` не вызываются вовсе (панель браузера не отрисовывает кадры). Поэтому в
консоли оставлена `window.wptMapDiagnostics()`:

| поле | что означает |
|------|--------------|
| `container` | фактический размер элемента `#map` |
| `leaflet` | размер, который считает своим сам Leaflet |
| `tiles` / `loaded` | сколько тайлов создано и загружено |
| `invisible` | загруженные тайлы с `opacity < 1` (застрявшая анимация проявления) |
| `chain` | высоты `#app` / `#view-root` / `.map-view` / слота / нижнего меню |
| `dvh` | `window.innerHeight` |

Как читать: расхождение `container` и `leaflet` — устаревший размер у Leaflet; ноль в
`chain` — схлопнувшаяся flex-цепочка; здоровые числа при пустой карте — смещение полотна.

**История для тех, кто столкнётся снова.** Причину нашли только замеры с телефона:
контейнер схлопывался в нулевую высоту, а Leaflet держал 4121px. Четыре версии до этого
оказались неверными — сеть, размер по угаданному таймингу, выброшенные тайлы,
застрявшая прозрачность. Защиты от всех четырёх остались в коде и полезны сами по себе:
- `ensureMapSized()` — сверяет размер Leaflet с реальным и подпирает схлопнувшийся
  контейнер явной высотой; подпорка снимается только после проверки, что высота держится
  без неё (иначе получается колебание);
- `refreshMapAfterResume()` — при возврате из фона перезапрашивает тайлы, потому что
  проверка размеров этот случай закрыть не может по построению;
- `fadeAnimation: false` — анимация проявления тайлов идёт через rAF и у свёрнутого PWA
  может застрять незавершённой.
