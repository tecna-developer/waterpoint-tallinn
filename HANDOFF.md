# WaterPoint Tallinn — контекст проекта (handoff)

Саммери для продолжения работы в другой сессии.

## Что это
PWA-прототип для поиска общественных питьевых кранов **и общественных туалетов** в
Таллине. Сделан по макетам Stitch («WaterPoint Tallinn», светлая тема).

## Какому ТЗ соответствует
Актуальный документ — [`TZ_WaterPoint_Tallinn_with_public_toilets.md`](TZ_WaterPoint_Tallinn_with_public_toilets.md)
(«VeeLähedal», v0.1 от 05.07.2026, со слоем туалетов). **Важно:** более ранняя версия
ТЗ (v1.0 от 15.07.2026, `.docx`, в репозиторий не входит) использовала другую нумерацию
FR — там FR-11 была админ-панелью, а FR-12 аналитикой. Вся документация и комментарии в
коде приведены к нумерации актуального документа (FR-01…FR-17); при сверке со старыми
записями это первое место, где легко запутаться.

## Стек
Vite + ванильный JS (без фреймворка) + Leaflet (карта, тайлы CARTO/OSM).
Деплой на GitHub Pages автоматически при пуше в `main` через `.github/workflows/deploy.yml`.

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # сборка в dist/
```

## Структура (`src/`)
- `main.js` — вся логика и рендер вью (онбординг, карта, список, карточка, избранное,
  настройки, фильтры, форма отчёта, легенда)
- `data.js` — конфиг слоёв, синхронизация с ArcGIS, кеш, localStorage, статусы, тема
- `data/waterpoints.json` — снапшот 78 кранов
- `data/toilets.json` — снапшот 96 туалетов
- `i18n.js` — строки ET/EN/RU + автовыбор языка по устройству
- `icons.js` — SVG-иконки, `markerSvg(category, status, selected)`, `thumbSvg(category)`
- `styles.css` — стили, светлая/тёмная темы
- `../scripts/gen-toilets.mjs` — генерация снапшота туалетов из GIS

## Источники данных
Два независимых слоя Tallinn GIS ArcGIS REST в одной модели точки, различаются полем
`category` (§6.2 ТЗ):

| category | Слой | Точек |
|----------|------|-------|
| `water_tap` | `veebikaart/Veev6tukohad` | 78 |
| `public_toilet` | `veebikaart/avalikud_tualetid` (слой 0) | 96 |

Слой туалетов был открытым вопросом ТЗ (§13) — источник найден и проверён запросами.
Слой 0 является superset'ом: слой 1 («Statsionaarsed tualetid», 27 точек) целиком в него
входит по `objectid`, второй запрос не нужен. Из 106 записей 10 не имеют геометрии и
отбрасываются; остаются 69 временных и 27 стационарных.

Синхронизация слоёв независима (`Promise.allSettled`): сбой одного слоя не стирает
последнюю успешную копию другого. Районы вычислены point-in-polygon по `Linnaosad_asumid`.

**Чего в источниках нет:** часы работы, платность и доступность туалетов; миска для
собак и indoor/outdoor у кранов; фото. Всё это показывается как «нет данных» либо
скрывается (мёртвые фильтры), а не выдумывается — требование §6.3.

Временный туалет после даты демонтажа (`t2htaeg`) исчезает из выдачи — вести человека
к физически убранной точке хуже, чем не показать её.

## Реализовано
FR-01…FR-17 актуального ТЗ в объёме клиентского прототипа — подробная таблица со
статусами и оговорками в [README.md](README.md).

Частично закрыты:
- **FR-08** — чипы «с миской для собак» и indoor/outdoor скрыты (нет данных в источнике).
- **FR-09** — форма работает в честном демо-режиме: категории и комментарий
  сохраняются только в localStorage, контактные данные не собираются, отправки
  модератору нет; локальные отметки можно удалить в настройках.
- **FR-13** — «поделиться» есть (`navigator.share` + deep link `?p=<id>`), QR-кода нет.

## Ключевые правки последней сессии
- Слой общественных туалетов целиком: данные, маркеры, легенда, фильтр «Вода/Туалеты/Все»,
  карточка туалета, отдельные категории жалоб
- Онбординг с объяснением геолокации **до** системного запроса + ручной выбор точки
  отсчёта тапом по карте (FR-01, критерий приёмки №1)
- Эко-блок про refill, сезонное предупреждение, источник и дата проверки в карточке
- Автовыбор языка по `navigator.languages` (FR-11)
- Карта больше не пересоздаётся на каждый ререндер: контейнер живёт вне цикла рендера,
  обновляется только слой маркеров (§8, 174 точки)
- Поле отчёта `water_point_id` → `point_id`; старые записи на устройствах читаются

## Незакрытые задачи
1. **Название.** В ТЗ рабочее имя — **VeeLähedal**, в коде и на демо — WaterPoint Tallinn.
   С появлением туалетов «WaterPoint» больше не описывает продукт. Переименование
   затрагивает `index.html`, `manifest.webmanifest`, og-баннер, README и, возможно, URL
   репозитория и демо — решение отложено.
2. **Описание репозитория на GitHub** — задать вручную через ⚙ About на странице репо
   (или `gh auth login` + `gh repo edit`). Предлагаемый текст:
   `Поиск общественных питьевых кранов и туалетов в Таллине: карта и список точек, маршрут, фильтры. Интерфейс ET/EN/RU.`
   Website: `https://tecna-developer.github.io/waterpoint-tallinn/`
3. **Backend** (§9.2 ТЗ): приёмник жалоб, админ-модерация точек и статусов, доуточнение
   часов/платности/доступности туалетов вручную (Supabase/PostGIS).
4. **За пределами MVP** (§4.2): офлайн-тайлы карты, push-уведомления, личный аккаунт,
   геймификация, QR-код точки, другие города.
5. **Юридическое** (§12): подтвердить условия повторного использования обоих слоёв
   Tallinn GIS и не позиционировать приложение как официальное для Tallinna Vesi.

## Замечания по окружению
- ОС Windows, оболочка PowerShell; git выдаёт предупреждения LF→CRLF (не критично).
- `gh` CLI **не авторизован** — операции через GitHub API недоступны, только git push/pull.
- Порт 5173 бывает занят другим проектом — Vite сам переходит на 5174.
- Демо кешируется service worker'ом (`public/sw.js`). При релизе поднимать `CACHE`
  (сейчас `wpt-shell-v4`), иначе установленное PWA останется на старой оболочке.
  Логику воркера можно прогнать без браузера: `npm run test:sw`.
- **Обновление установленного PWA идёт с задержкой:** первый запуск после деплоя ещё
  работает на старом воркере, новый в это время только устанавливается. Чтобы увидеть
  изменения, приложение надо полностью закрыть (смахнуть из списка задач) и открыть
  **дважды**. Проверено на живом демо: первая перезагрузка отдавала прежний бандл.
- **Частые деплои подряд опасны для установленного PWA.** Каждая сборка меняет хеши
  файлов; если PWA стартует, когда свежий `index.html` уже отдаётся, а бандл ещё не
  разошёлся по CDN, скрипт не загружается. На этот случай в `index.html` есть аварийный
  блок (вне бандла): через 8 с пустого экрана показывает сообщение и кнопку, которая
  чистит кеши, снимает воркер и перезагружает.

## Отладка «карта не отображается»
Сбой воспроизводится только на реальном телефоне — в headless-окружении страница всегда
`document.hidden === true`, и ветка «возврат PWA из фона» недостижима. Поэтому в консоли
оставлена `window.wptMapDiagnostics()`; она возвращает:

| поле | что означает |
|------|--------------|
| `container` | фактический размер элемента `#map` |
| `leaflet` | размер, который считает своим сам Leaflet |
| `tiles` / `loaded` | сколько тайлов создано и загружено |
| `invisible` | загруженные тайлы с `opacity < 1` (застрявшая анимация проявления) |
| `chain` | высоты `#app` / `#view-root` / `.map-view` / слота / нижнего меню |
| `dvh` | `window.innerHeight` |

Расхождение `container` и `leaflet` означает устаревший размер у Leaflet; ноль в `chain`
— схлопнувшуюся flex-цепочку; здоровые числа при пустой карте — смещение полотна.
Именно эти замеры (снятые с телефона) вскрыли причину: контейнер схлопывался в нулевую
высоту, а Leaflet держал 4121px. Три версии до этого — сеть, размер по таймингу,
прозрачность тайлов — оказались неверными.
  Логику воркера можно прогнать без браузера: `npm run test:sw` (на localhost SW
  не регистрируется, живьём в дев-режиме его не проверить).
